この制作ログを庭のLog形式で出力してください。

出力ルール：

- TypeScriptのexport const形式
- slugは {{slug}}を使う
- slugからexport名を自動生成する
  例:
  covertcoffee-001 → covertcoffee001
  makuracover-002 → makuracover002
- typeは{{logType}}を使う
- createdAtはログ作成日
- title/categoryに整理する
- categoryは以下のいずれかから選択する：
   AI
   Webサイト構築
- categoryは必ず上記のいずれかを使用し、新しいcategoryを作らない

以下の6セクションに整理する：

1. purpose
2. policy
3. steps
4. execution
5. result
6. next

各項目のルール：

### purpose

このログで「何をやろうとしたのか」を整理する。

単なる作業内容ではなく、目的や背景を整理する。

### policy

このログで採用した考え方・方針・判断基準を整理する。

チャット内で方針が決まっていない場合は、無理に追加しない。

### steps

このログで実際に進めた手順を、時系列で整理する。

- string[]で出力する
- 実際に行った作業を整理する
- 細かすぎる操作はまとめる
- executionと対応する順番にする
- チャット内にない作業を推測して追加しない

### execution

実際に行った作業と、その内容・結果を整理する。

- { title: string; body: string }[]で出力する
- titleはstepsの内容と対応させる
- 実際に試したこと、変更したこと、確認したことを書く
- 試行錯誤や途中で発生した問題も、ログとして意味がある場合は残す
- executionの数とstepsの数は基本的に一致させる
- body内では、必要に応じて箇条書きを使用してよい
- 元のチャットにない事実や結果を追加しない

### result

このログを通して最終的にどうなったかを整理する。

- 実際に確認できた結果を書く
- 「分かったこと」もここに含める
- 技術的な結果だけでなく、方針や考え方がどう変わったかも整理する
- 元のチャットにない結果を推測して追加しない

### next

今後やりたいこと、残っている課題、次に試すことを整理する。

- string[]で出力する
- チャット内で実際に出てきた内容を優先する
- 今後の方針として明確になっているものを整理する
- 単なる思いつきや、チャット内に存在しない内容を追加しない

共通ルール：

- チャット内の発言や試行錯誤をもとに整理する
- 元のチャットにない事実・結果・作業を推測して追加しない
- チャット内で考え方が変わった場合は、policy / result / nextなど適切な項目に反映する
- 同じ内容を複数のセクションへ重複して書きすぎない
- 開発の意思決定や、何を試してどうなったかが分かる内容を優先する
- 単なる会話や細かい操作ログは必要に応じて整理・省略する
- 情報がない項目は空文字または空配列でよい
- 不要な項目は空配列でOK
- template literal内に不要な空行を入れない
- template literalの先頭・末尾にも空行を入れない
- 意味のある改行はそのまま残す
- TypeScriptの型エラーが出ないコードを生成する

mediaについて：

- mediaは空配列で出力する
- 画像・動画の追加は別工程で行う

sourceについて：

- source.titleは{{chatTitle}}を使う
- source.urlは{{chatUrl}}を使う

relatedについて：

- 関連するログや参考リンクがチャット内に存在する場合のみ追加する
- 関連情報がない場合は空配列にする
- 元のチャットにないURLを推測して追加しない

出力形式：
